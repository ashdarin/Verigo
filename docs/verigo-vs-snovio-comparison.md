# Verigo 与 Snov.io 完整对比

> 目的：把已体验到的 Snov.io 工作台规律，转换为 Verigo 可执行的产品判断。  
> 原则：只比较产品结构、流程、体验和已知事实；不复制 Snov.io 的代码、品牌、文案、评价、客户数据或未经授权的信息。  
> 版本基线：Verigo 当前代码与已发布的 Workspace 改造版本（提交 `0273115`）。

## 1. 总体判断

| 维度 | Verigo | Snov.io | 判断 |
| --- | --- | --- | --- |
| 核心定位 | 邮箱验证、批量清洗、企业邮箱查找 | 面向潜客开发的综合工作台 | Verigo 更专注，Snov.io 更广 |
| 首次使用 | 单个邮箱验证路径直接 | 进入产品分组和工作台，再选择任务 | Verigo 的启动速度更快 |
| 登录后体验 | 已有 Workspace、最近任务、额度、可投递率、快速入口 | 完整的潜客、公司、数据库、营销、CRM、账户工作台 | Verigo 的骨架已建立，但对象和流程仍少 |
| 结果处理 | 验证结果、任务历史、下载和 API 能力 | 保存、筛选、列表、导出、营销、CRM 等持续处理 | Verigo 需要加强结果复用 |
| 批量任务 | 文件导入、额度扣除、任务状态、下载 | 大规模批量工作流和更完整的任务管理 | Verigo 应先把规则透明和任务闭环做深 |
| 企业邮箱查找 | 姓名/域名候选生成和验证 | 多种搜索入口、筛选、潜客数据库和列表 | Verigo 应做可持续列表，而非一次性生成 |
| 价格与账户 | 按额度计费、钱包、API Key、账户安全 | 套餐、点数、收件人、团队、集成和高级账户体系 | Verigo 需要更完整的使用量与账单解释 |
| 视觉第一印象 | 已从工具页向专业 SaaS 工作台改造 | 成熟 SaaS 导航、分组、对象列表和账户层级 | Verigo 的首屏改善明显，但深度仍有差距 |

## 2. 第一印象对比

### Verigo 当前优势

- 首屏主任务明确：验证一个邮箱是否可投递。
- 单个验证低摩擦，适合首次尝试。
- 结果字段相对透明，包含状态、验证方式和服务器响应。
- 批量清洗和企业邮箱查找被放在次级入口，不再与单个验证竞争。
- 已有可用额度、今日处理量、可投递率、最近任务和快速开始入口。

### Verigo 当前不足

- 产品对象仍偏少，企业邮箱查找还没有完整的列表资产、保存和复用层。
- 导航虽然有模块，但部分能力仍依赖单页状态切换，和成熟 SaaS 的独立模块感有差距。
- 账户设置仍集中在较轻量的菜单和对话框，使用量、额度流水、API 使用记录、通知中心、数据删除等需要更独立的账户信息架构。
- 公开页面和产品页的中文、英文、规则说明需要持续维护，避免静态文案和动态状态口径不一致。
- 没有 Snov.io 那样的触达、回复、CRM 和团队协作闭环；这不是当前阶段必须复制的能力，但应明确未来边界。

### 结论

Verigo 不需要把首屏变成“功能超市”。更好的方向是：让一个邮箱验证动作足够快，再让登录后的 Workspace 足够完整，逐步把结果变成可保存、可导出、可复用的工作资产。

## 3.1 真实操作后的流程差距

### 单个验证

| 步骤 | Snov.io 实际表现 | Verigo 当前表现 | 应吸收的做法 |
| --- | --- | --- | --- |
| 输入 | 输入框和明确的验证按钮，输入后才允许提交 | 输入邮箱后提交单个验证 | 保持低摩擦，并在输入前后给出清晰状态 |
| 结果 | 当前页追加联系人结果卡片 | 当前页展示结果表格和详情 | 增加结果卡片摘要和后续动作 |
| 后续动作 | 添加至列表、发送邮件、历史验证 | 查看详情、复制、下载、历史和 API | 增加“保存到列表”，不直接加入发信能力 |
| 历史 | 同页显示以前验证过的邮箱和完成次数 | 有任务历史和最近任务 | 增加按邮箱/任务的历史关联 |
| 空/异常 | 结果对象和历史区域仍保持结构 | 结果状态有 unknown、失败等 | 保持统一结果对象，不让空状态变成死胡同 |

### 单个查找

| 步骤 | Snov.io 实际表现 | Verigo 当前表现 | 差距 |
| --- | --- | --- | --- |
| 输入字段 | 名字、姓氏、公司网站域名 | 姓名、公司域名候选生成 | Verigo 需要补充职位、部门、地点等可选上下文 |
| 无结果 | 明确显示“未找到邮箱地址”，并保留查找历史 | 可显示没有可确认地址 | 统一“生成候选”和“验证候选”的解释 |
| 历史 | 完成次数和历史条目在当前页可见 | 主要在任务历史中查看 | 查找历史应独立可见 |
| 后续动作 | 添加至列表、发送邮件 | 验证候选、导出/API 方向 | 优先做保存列表和导出，不复制发信动作 |

### 域名搜索与数据库搜索

Snov.io 的域名搜索支持 URL 查询参数和可复制结果路径；数据库搜索的职位筛选是异步候选搜索，并区分包含/排除。Verigo 的企业邮箱查找目前更像一个明确的表单，适合先补齐：

1. 可选的职位、部门、地点和公司规模。
2. 候选条件的已选标签和移除动作。
3. 结果数量、搜索历史和 URL/任务可复用。
4. 空结果原因和重新搜索入口。

### 批量验证

Snov.io 实际体验显示：格式、100,000 行规模、上传入口和套餐限制会在提交前出现；试用账户上传后会明确提示批量功能需要升级，并展示解锁内容。Verigo 应做到类似的“早提示”，但用自己的真实额度规则表达：

- 支持格式和 5 MB 限制。
- 单次最大处理量。
- 预计处理时间。
- “提交后将消耗 N 个额度”。
- 额度不足时直接去购买额度。
- 失败、停止、部分完成和 Yahoo 的扣费规则。

## 3.2 Snov.io 真实体验对 Verigo 的新增启发

1. **结果要成为对象**：验证结果不只是表格行，还可以被保存、再次打开、加入列表或作为下一步输入。
2. **空结果也要可继续**：`example.com` 查找没有结果，但页面仍有历史、时间和后续动作，用户知道系统确实完成了任务。
3. **筛选器要渐进披露**：先输入职位，再异步给候选标准项，再选择包括/排除，避免一次显示过多复杂选项。
4. **权限限制应提前表达**：批量上传后立即显示升级门槛，不让用户在最后提交时才遇到意外限制。
5. **首次进入必须有一个动作**：送达率是运行测试，预热是预热邮箱，CRM 是创建第一笔交易；Verigo 的 Workspace 空状态应同样提供单个验证、批量清洗和企业邮箱查找三个入口。
6. **账户是产品教育层**：价格、使用量、安全、通知和 API 并非后台杂项，而是帮助用户理解长期使用成本和边界的产品页面。

## 3.3 可量化但不应照搬的事实

本轮页面实际显示过一些 Snov.io 自己的套餐或宣传数字，例如 100,000 行批量规模、5,000 多种集成、套餐点数和收件人等。这些数字只能作为“它如何表达资源单位”的观察，不能转写成 Verigo 的能力或宣传。Verigo 只有在自己的后端、账单和运行数据能够证明时，才可以展示类似数字。

## 4. 关键任务流程对比

### 4.1 单个邮箱验证

**Verigo**：首页 -> 输入地址 -> 验证 -> 查看状态和服务器响应。  
**Snov.io**：单独验证入口 -> 输入地址 -> 查看验证结果，并可进入更大的潜客或触达工作流。

**Verigo 应保持的优势**：路径短、结果字段清楚、免费单个验证容易开始。  
**Verigo 应补的能力**：结果保存、加入列表、复制字段、查看相关任务和从结果继续处理。

### 4.2 批量清洗

**Verigo 当前**：支持手动粘贴、TXT/CSV/JSON/XLSX/XLSM/XLS 导入、任务进度、停止/恢复、结果过滤和 CSV 下载。  
**Snov.io 参考**：批量任务更像可跟踪的工作流程，用户更容易理解规模、额度和结果去向。

**差距清单**：

- 提交前应明确“将消耗 N 个额度”。
- 说明单文件大小、单次最大地址量和预计处理时间。
- 说明失败、停止、部分完成和无法入队时的扣费规则。
- 明确 Yahoo 是否扣费、unknown 如何处理。
- 下载格式、字段和结果状态必须在提交前可见。

### 4.3 企业邮箱查找

**Verigo 当前**：输入姓名和公司域名，生成候选邮箱并验证。  
**Snov.io 参考**：查找是持续使用的数据库/工作台能力，用户可以筛选、保存、导出并回到历史。

**建议的 Verigo 目标对象**：

```text
查找任务
  -> 候选邮箱
      -> 验证状态
      -> 结果置信度
      -> 保存到列表
      -> 导出 / API
      -> 历史任务
```

Verigo 不需要立刻拥有完整联系人数据库，但必须让用户觉得这项能力可以反复使用。

### 4.4 账户工作台

**Verigo 已具备**：Workspace、剩余额度、今日已处理、可投递率、最近任务、三个快速入口、API 文档/Key 入口。  
**仍需加强**：使用量趋势、额度流水、任务历史过滤、API 使用记录、通知中心、账户安全、数据删除和帮助中心的统一入口。

## 6. 业务和合规边界

### 可以借鉴

- 产品分组和工作台层级。
- 搜索、验证、保存、导出、历史的任务闭环。
- 额度、点数、套餐、API 和账户设置的解释方式。
- 状态、筛选、空状态、错误和帮助的交互模式。

### 不可以直接搬用

- Snov.io 的 Logo、品牌、颜色、代码、文案、截图和评价。
- Snov.io 的客户 Logo、客户名单、联系人数据库或未经授权的数据。
- 没有 Verigo 真实证据的成功率、准确率、用户数、处理量或合作伙伴。
- 通过“看起来像 Snov.io”来误导用户认为两者有合作或隶属关系。

## 7. Verigo 产品路线图

### P0：已经完成或正在稳定

- 公开首页聚焦单个邮箱验证。
- 结果预览、验证方式、服务器响应和限制说明。
- 登录后的 Workspace 独立入口。
- 最近任务、额度、今日处理量、可投递率和快速入口。
- 单个、批量、企业邮箱查找、历史、钱包、API Key。
- `/workspace`、`/history` 深链接和登录保护。
- 中文/英文动态文案和多视口基础适配。

### P1：下一阶段必须完成

1. **统一账户中心**：使用量、额度流水、任务历史、API 使用、邮箱验证、安全、通知和数据删除分组展示。
2. **查找工作台**：保存列表、联系人字段、职位/部门/地点、置信度、验证状态和历史任务。
3. **批量规则透明**：提交前额度确认、失败/停止/部分完成处理、Yahoo 计费和下载字段说明。
4. **API 运营能力**：API 调用记录、错误日志、限额、密钥权限和撤销确认。
5. **统一设计系统**：按钮、间距、圆角、状态颜色、表格、卡片、空状态和移动端组件。

### P2：产品成熟后评估

- 团队成员和权限。
- 任务模板和重复任务。
- Webhook、CRM 和表单集成。
- 送达率监控和发信前名单策略。
- 更高级的公司/联系人对象模型。
- 合规前提下的 AI 辅助解释、字段补全和任务建议。

## 8. 验收标准

每个阶段都应使用真实用户路径验收，而不是只看页面是否能打开：

- 游客首页只有一个清晰主任务。
- 注册、登录失败、登录成功、退出和过期会话反馈明确。
- 普通用户进入 Workspace，管理员仍能进入管理功能。
- 单个、批量、企业邮箱查找、历史、额度、价格、API Key 路径可完成。
- 额度不足、Yahoo、unknown、Catch-all、停止和部分完成都有可解释反馈。
- 中文和英文动态状态不混用。
- 390px、768px、1440px 无横向溢出。
- 浏览器前进后退、深链接和刷新后状态稳定。
- 页面无 console error，动态数据加载完成后导航状态稳定。
- 真实数据、真实规则和未授权品牌信息严格分离。

## 9. 最终产品判断

Snov.io 的优势是广度、对象模型和持续工作流；Verigo 的优势是验证动作简单、结果解释直接、产品边界更聚焦。Verigo 不应该追求“做成另一个 Snov.io”，而应该形成自己的组合：

> **最快的单邮箱验证 + 可解释的批量清洗 + 可持续的企业邮箱查找 + 可信的额度与账户工作台。**

如果这四件事形成闭环，Verigo 即使没有 Snov.io 的营销、CRM 和数据库规模，也能成为一个可信、专注、可持续使用的邮箱质量产品。
